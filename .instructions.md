# Rust Conductor — Agent Instructions

## Project Overview
Rust-based Conductor-compliant workflow orchestrator with React/TypeScript frontend.

## Architecture
- **backend/** — Rust (Actix-web 4, sqlx/Postgres, deadpool-redis)
- **frontend/** — React 19, TypeScript, Vite, Tailwind 4, shadcn/ui (new-york style, stone base)
- **Docker** — docker-compose with postgres:17, redis:8, multi-stage builds

## Backend Structure
```
backend/src/
├── main.rs          # Entry point, HTTP server setup
├── config.rs        # Env-based config (HOST, PORT, DATABASE_URL, REDIS_URL)
├── models/          # Serde structs matching Conductor OpenAPI spec
│   ├── mod.rs       # Re-exports all submodules via pub use
│   ├── common.rs    # Shared types (SearchResult, BulkResponse, SchemaDef)
│   ├── workflow.rs  # WorkflowDef, Workflow, StartWorkflowRequest, etc.
│   ├── task.rs      # TaskDef, TaskResult, PollTask, TaskUpdateRequest
│   ├── event.rs     # EventHandler, EventAction
│   ├── health.rs    # Health, HealthCheckStatus
│   └── search.rs    # WorkflowSummary, TaskSummary
├── engine/mod.rs    # Core logic: CRUD, execution, polling, bulk ops
├── store/
│   ├── postgres.rs  # PgPool + migrations (workflow, task, task_log, event_handler, config tables)
│   └── redis.rs     # Deadpool Redis pool
└── api/
    ├── mod.rs       # Route tree under /api/ + /health
    ├── metadata.rs  # /api/metadata — workflow & task def CRUD
    ├── workflow.rs   # /api/workflow — execution, search, decide, rerun, skip
    ├── tasks.rs      # /api/tasks — poll, batch_poll, update, ack, logs, search
    ├── event.rs      # /api/event — event handler CRUD
    ├── admin.rs      # /api/admin + /api/queue — config, sweep, pause/resume queues
    └── bulk.rs       # /api/workflow/bulk — pause/resume/retry/restart/terminate
```

## Key Conventions
- All model fields use `#[serde(rename_all = "camelCase")]`
- Models import from `crate::models::*` (glob re-export)
- Engine methods return `Result<T, EngineError>`
- `EngineError` implements `actix_web::ResponseError`
- SQL uses raw queries via `sqlx::query` / `sqlx::query_as` / `sqlx::query_scalar`
- Redis used for task queues (`conductor:queue:{taskType}`) and queue pause state
- Workflow defs and task defs stored as JSONB in Postgres

## Commands
- `cargo check` — type check backend
- `cargo build --release` — build backend
- `npm run dev` — run frontend dev server (from frontend/)
- `docker compose up --build` — full stack

## API Compliance
Models and endpoints follow the Conductor OpenAPI 3.0.1 spec at `http://192.168.31.236:8128/api-docs`. When adding endpoints, match the Swagger path/method/request/response exactly.
